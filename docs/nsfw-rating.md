# 区分の自動判定(sfw / suggestive / explicit)

作品の区分(`content_rating`)の「案」を、AIが自動で出す仕組みと、今後の予定。実装は `core/nsfw.py`、露出の検出は `core/autodetect.py`。
**確定値は、あくまで人が承認した `content_rating`**(ADR-0008)。自動判定(`nsfw_auto_rating`・`nsfw_auto_confidence`)は、参考値。

## 現在の仕組み(第1段階。実装済み)

### 入力
1. **NSFWスコア**: `Marqo/nsfw-image-detection-384`(ADR-0009)。SFW/NSFWの二値分類器で、出力は0〜1のスコア
   - 画像は、**切り取らず、全体を384×384に縮めて**渡す(既定は中央の切り取りで、縦長の画像は上下が判定に使われなかった)
   - 動画は、一定間隔(既定2秒、最大60コマ)でコマを調べ、**スコアが高いほうの数コマ(既定3)の平均**を、動画のスコアにする(1コマの誤検出で、動画全体が決まらないように)
2. **露出した部位の検出**: NudeNet(`pip install -e ".[detect]"`。入っていなければ使わない)。性器・肛門(genital)と、胸・臀部(chest)が写っているか
   - 動画は、調べたコマが3以下なら1コマ、それより多ければ2コマ以上で見つかったときに「写っている」とする

### 3段階の案の決め方(`decide_rating`)
| 露出の検出 | スコア | 案 |
|---|---|---|
| 性器・肛門が写っている | (問わない) | explicit |
| 胸・臀部が写っている | explicitのしきい値以上(既定0.8) | explicit |
| 胸・臀部が写っている | 未満 | suggestive |
| 露出が見つからない(検出器なしを含む) | suggestiveのしきい値以上(既定0.5) | suggestive |
| 露出が見つからない | 未満 | sfw |

### 「要確認」
スコアが、下限(既定0.2)以上、上限(既定0.8)未満の作品。一覧のアイコンの枠が点線になり、絞り込み「AI判定」の「要確認」で見られる。迷う作品を、人の目で確かめるための印。

### 設定で調整できる値(設定の「区分の判定」タブ。`nsfw_params` として設定テーブルに保存)
suggestiveのしきい値 / explicitのしきい値 / 「要確認」の下限・上限 / 動画で平均するコマの数 / 露出の検出の感度。
保存した値は、**次の判定から**使われる(ワーカーの再起動は要らない)。

### 判定し直し(同じタブの「判定し直し」)
保存したしきい値で、判定し直しを、ジョブキュー(`ai_tasks` の `nsfw`)に積む。対象は、種類(画像/動画/両方)と範囲(未判定・旧形式のみ/要確認のみ/すべて)で選ぶ。
処理は、ワーカーが、AI処理の負荷設定の範囲で順に行う(画像は1枚約0.4秒、動画は1本数秒〜数十秒)。人が承認した区分は、変わらない。判定し直すと、前の自動タグ(sfw/nsfw/suggestive/explicit)は付け替わる。
旧形式の判定(`nsfw`)は、画面上では explicit と同じ扱い。判定し直すまで残る。

### 既知の限界
- Marqoモデルは、AI生成のグラビア調・イラスト調で、不安定になりやすい。NudeNetも軽量版(320n)で、小さく写った対象は見逃しやすい
- 実データ(2026-10-28)では、旧判定のnsfw(画像)のうち、露出した部位が検出されたのは約2割。残りは「きわどいが、露出はない」画像と見られる(NudeNetの見逃しの可能性もあり、断定はできない)
- 精度の評価に使える、人が承認した区分のデータが、まだ少ない(2026-10-28時点で12件)

## 将来の予定(第2段階。**いまはやらない**)
**人が承認した区分から学習する、3段階の分類器**を作り、第1段階の結果と置き換える(または、組み合わせる)。

- **方式**: Marqoモデルの最後の1層(192次元→2択)を外し、画像の192次元の特徴量(1枚0.1秒)を取り出して、これを入力に、**3段階(sfw/suggestive/explicit)を出す小さな分類器**(ロジスティック回帰など)を学習する。モデル本体の再学習は、しない。CPUで、数秒で学習できる
  - 動画は、コマごとの特徴量を、上位コマの平均などでまとめる
  - 露出の検出(NudeNet)の結果も、特徴量として足せる
- **必要なデータ**: 人が承認した区分(`content_rating_confirmed = 1`)。目安は、**各区分で30〜50件以上**(少ない区分があると、精度が出ない)。一覧の「区分を一括承認」で、自然に増やせる
- **評価**: 承認済みのデータを分けて(交差検証)、第1段階の結果と、正解率・区分ごとの混同(特に、suggestiveとexplicitの取り違え)を比べる。良くなったときだけ、切り替える
- **運用**: 学習は、設定画面のボタン(または`reelmilly`のコマンド)で実行する。学習済みの分類器は、`data/state/` に保存する。承認済みのデータが増えたら、学習し直せる
- **注意**: 学習に使うのは、利用者が承認した区分だけ。外部に送らない(すべて、このPC内)
- 判断のきっかけ: 承認済みの作品が、各区分で数十件たまったとき、または、第1段階の精度に、不満が続くとき
