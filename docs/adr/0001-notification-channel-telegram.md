# 0001. 通知・操作チャネルをTelegramに一本化する

- ステータス: 決定
- 決定日: 2026-09-15
- 決定者: プロジェクトオーナー

## コンテキストと課題

ingest通知、承認、失敗通知、コマンド操作など、ユーザーとワーカー間のやり取りをどのチャネルで行うかを決める必要がある。候補としてDiscord、Slack、メール、Telegramがある。

## 検討した選択肢

- Discord
- Slack
- メール
- Telegram

## 決定

Telegram Bot（`Reelmilly`）に一本化する。Bot APIのロングポーリングで単一ユーザー運用に十分対応でき、ボタン付きメッセージ（承認・スキップ等）にも対応しているため。

## 結果

### 良い影響

- 通知チャネルが単一になり、実装・運用がシンプルになる
- ボタンUIで承認フローを完結できる

### 悪い影響・トレードオフ

- Discord/Slack等の既存ワークフローに統合したい場合は別途対応が必要になる
