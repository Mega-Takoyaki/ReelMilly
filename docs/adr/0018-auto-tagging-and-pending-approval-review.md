# 0018. 内容説明生成時のタグ自動提案と、承認待ちアセットのレビュー動線

- ステータス: 決定
- 決定日: 2026-09-27
- 決定者: プロジェクトオーナー

## コンテキストと課題

[ADR-0015](0015-ai-content-description-and-caption-generation.md)で画像内容説明・Fanvue投稿文の自動生成を実装した後、プロジェクトオーナーより以下の要望があった。

1. NSFW自動仕分け・内容説明の取得は定期的に非同期で行い、判定待ちの作品を後でまとめて承認して`ready`にできるようにしたい
2. 内容説明の生成時に、タグもいくつか自動付与してほしい
3. NSFW自動仕分けの結果（`nsfw_auto_rating`）も、補足情報として提示（タグとして）してよいのではないか

1点目を調査した結果、`reelmilly analyze`（`watch`ループから定期実行）による非同期の分析自体は既に実装済みだったが、**本体UIに「承認待ちのみ」を絞り込むフィルタが無く**、後でまとめてレビュー・承認する動線が弱いことが判明した（`status="ready"`はNSFW自動仕分け・内容説明の両方が揃えば人間の承認なしで自動的になる。人間の承認＝`content_rating_confirmed`は別軸で、Fanvue自動投稿の可否にのみ使われる）。

## 決定

### 1. 一覧画面に「承認状態」フィルタと一括選択を追加

- `db.list_assets`に`confirmed`引数（`True`/`False`/`None`のtri-state）を追加し、承認済み/承認待ちで絞り込めるようにする
- 一覧画面のフィルタに「承認状態」（すべて/承認待ち/承認済み）を追加する
- 「承認待ち」×「表示中をすべて選択」ボタンを組み合わせることで、定期分析で溜まった`ready`状態のアセットをまとめてレビュー・一括承認できるようにする（既存の一括承認機能`/assets/bulk/confirm`と組み合わせて使う）

### 2. 内容説明生成時にタグを自動提案する

`Generator.describe_image`の戻り値を、説明文の文字列から`DescriptionResult`（`description`と`suggested_tags`のペア）に変更する。システムプロンプト（`core/settings.py`の`DEFAULT_DESCRIPTION_SYSTEM_PROMPT`）を更新し、モデルに次の2行形式での出力を指示する。

```
説明: <内容説明>
タグ: <タグ1>, <タグ2>, <タグ3>
```

`core/generation.py`の`_parse_description_response`でこの形式をパースする。モデルがこの形式に従わない場合は、応答全体を説明文として扱いタグは空にする（フォーマット崩れでパイプライン全体を失敗させないため）。タグ数は`MAX_SUGGESTED_TAGS`（5個）で上限を設ける。

この変更はClaude API/OpenAI API/自前ホスト型VLM（[ADR-0017](0017-local-vlm-for-explicit-content.md)）の3プロバイダーすべてに共通で適用する。

### 3. NSFW自動仕分け結果もタグとして付与する

`core/analysis.py`に`apply_auto_tags(conn, asset_id, result)`を追加し、以下をタグとして自動付与する。

- 内容説明生成時にAIが提案したタグ（`suggested_tags`）
- NSFW自動仕分けの結果（`nsfw_auto_rating`の値、`sfw`または`nsfw`をそのままタグ名にする）

`ingest_inbox`（ingest時）と`cmd_analyze`（再試行時）の両方から呼び出す。`AnalysisResult.success`が`False`（片方のみ成功）の場合でも、取得できた分のタグは付与する。既存のタグ絞り込みUIでNSFW自動仕分け結果によるフィルタが行えるようになる。

## 結果

### 良い影響

- 定期実行で溜まった`ready`状態のアセットを、「承認待ち」フィルタ＋一括選択＋一括承認の組み合わせで効率的にレビューできるようになった
- タグが自動的に増えることで、後からの検索・整理が楽になる
- NSFW自動仕分け結果をタグとしても持つことで、一覧画面の既存のタグ絞り込みから確認できるようになる（従来はアセット詳細画面の表示とバッジのみだった）

### 悪い影響・トレードオフ

- `describe_image`の戻り値の型変更は、3プロバイダーすべてに影響する破壊的変更である（本プロジェクト内で完結する変更のため実害はないが、将来Generatorインターフェースを外部に公開する場合は注意が必要）
- タグの自動生成品質はモデル・プロンプトに依存する。小型の自前ホスト型VLM（[ADR-0017](0017-local-vlm-for-explicit-content.md)）では、2行形式の指示に従わずタグが得られないケースが実機で発生する可能性がある（未検証、TODO.md参照）
- `nsfw`/`sfw`という同じ文字列が、`nsfw_auto_rating`カラムの値・タグ名の両方に使われることになり、概念としては重複がある。実害はないと判断し、シンプルさを優先した
