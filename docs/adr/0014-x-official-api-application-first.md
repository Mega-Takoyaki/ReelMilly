# 0014. X投稿は公式APIを採用する（申請ファースト）

- ステータス: 決定（[ADR-0002](0002-x-posting-via-playwright.md)を置き換える）
- 決定日: 2026-09-26
- 決定者: プロジェクトオーナー

## コンテキストと課題

[ADR-0002](0002-x-posting-via-playwright.md)では「公式APIの課金・申請コストを避ける」ためPlaywright非公式操作を採用した。しかし以下の事実が判明し、この前提が崩れた。

- 2026年2月6日、X APIは旧来の固定サブスクリプション（Basic $200/月、Pro $5,000/月）を廃止し、Pay-Per-Use（従量課金）に一本化された。投稿1件$0.015、リンク付き投稿$0.20、読み取り1件$0.005
- ReelMillyの想定投稿頻度（`drop`毎日1回＋リンク付き、`x_teaser`毎日1回、`x_engagement`週2回）で試算すると、月間コストはおよそ$6〜10程度
- X API v2は`POST /2/tweets`（テキスト最大280文字）と`POST /2/media/upload`（chunked upload、画像・動画対応）を提供しており、ReelMillyが必要とする投稿機能を満たせる。レート制限（100リクエスト/15分/ユーザー等）もReelMillyの低頻度運用には十分な余裕がある
- 一方、Playwright側はXのbot検出強化により、無加工では検出されやすく、2〜4週間ごとの継続的なメンテナンス（検出回避策の更新）が実務上必要という報告が複数ある。加えてアカウント凍結・規約違反のリスクは変わらず残る

コストの差がほぼ無視できる水準になった以上、Playwright実装（ヘッドレス検出回避、セレクタ保守、ログイン管理、失敗時スクショ処理）に投資する合理性は薄い。

## 検討した選択肢

- Playwright非公式操作を継続する（[ADR-0002](0002-x-posting-via-playwright.md)のまま）
- 最初から公式APIで実装する
- 開発者アプリを先に申請し、承認後は公式APIで実装する。審査が長期化する、または承認されない場合のみPlaywrightをフォールバックとして検討する（申請ファースト）

## 決定

3番目の「申請ファースト」を採用する。

- 今すぐX Developer Portalで開発者アプリを申請する
- 承認を待つ間は、SNS投稿と無関係な本体側（Phase 0／Phase 1／Phase 1.5）の実装を先に進める
- 承認され次第、Phase 2/3相当のX投稿実装は**公式APIで行う**。Playwrightは書かない
- 万一、審査が長期化する、または何らかの理由で承認されないことが判明した場合に限り、Playwrightをフォールバックとして再検討する（[ADR-0002](0002-x-posting-via-playwright.md)の内容を参照）

[ADR-0013](0013-sns-posting-as-logical-plugin.md)で本体とSNS投稿モジュールを論理分離しているため、この切り替えは`posting`モジュール内に閉じ、本体（画像管理アプリ）には影響しない。

## 結果

### 良い影響

- アカウント凍結・規約違反リスクがなくなる
- Playwrightの継続的なメンテナンス（bot検出回避策の更新）が不要になる
- ブラウザ実行環境（永続プロファイル、GUI起動、ヘッドレス制約）が不要になるため、[ADR-0005](0005-deployment-environment.md)のデプロイ環境の検討がシンプルになる（本体・SNS投稿モジュールともに、サーバーレス環境を含め自由に配置できる）
- 実装コストが下がる（セレクタ保守・失敗時スクショ処理・ログイン管理が丸ごと不要）

### 悪い影響・トレードオフ

- 月$6〜10程度のランニングコストが発生する（Playwrightなら電気代のみ）
- 開発者アプリの審査結果・所要期間が不透明で、計画通りに進まない可能性がある
- 万一Playwrightへのフォールバックが必要になった場合、[ADR-0002](0002-x-posting-via-playwright.md)の内容に基づく実装を別途行う必要がある
