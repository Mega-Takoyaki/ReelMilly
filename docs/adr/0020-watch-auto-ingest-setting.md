# 0020. watchループにフォルダ自動取り込み(ingest)を設定でオン/オフ可能な形で追加する

- ステータス: 決定
- 決定日: 2026-09-27
- 決定者: プロジェクトオーナー

## コンテキストと課題

プロジェクトオーナーから、ローカルディスクの指定フォルダ（`inbox`）に画像を置くだけで自動的に取り込まれるかという質問があった。調査の結果、以下が判明した。

- `reelmilly ingest`（`core/ingest.py`の`ingest_inbox`）は`inbox`フォルダのファイルをアプリ管理下の`ready/<アセットID>/`フォルダへ**移動**（コピーではない）しており、複製による容量増大は発生しない
- ただし`reelmilly watch`（常駐プロセス）は`analyze`（分析待ちの再試行）と`run-due`（投稿）のみを繰り返しており、**`ingest`は含まれていない**。そのため、`inbox`にファイルを置いただけでは自動的には取り込まれず、`reelmilly ingest`の手動実行またはWeb UIのドラッグ&ドロップアップロードが必要だった

プロジェクトオーナーは「取り込み方式は現状の移動方式のままでよい」「`watch`にingestを組み込むが、設定でオン/オフできるようにし、オンの時だけ定期的にingestを実行する」ことを希望した。

## 決定

`reelmilly watch`のループ内で、設定（`settings`テーブル、キー`watch_auto_ingest`）が有効な場合のみ`cmd_ingest`（＝`ingest_inbox`）を毎回実行する。

- 既定値は`False`（無効）とする。既存の運用（手動ingestまたはドラッグ&ドロップ）に影響を与えないため
- 本体UIの設定画面（`/settings`）にチェックボックス「inboxフォルダの自動取り込みを有効にする」を追加し、[ADR-0015](0015-ai-content-description-and-caption-generation.md)の生成AI設定と同じ`settings`テーブル経由の仕組みで保存する
- `cmd_watch`は毎ループでDBから設定値を読み直すため、`watch`プロセスを再起動しなくても、Web UIでの切り替えが次のループから反映される
- ループ内の実行順序は「ingest（新規ファイルの取り込み・即時分析）→ analyze（取り込み済みだが未完了のものの再試行）→ run-due（投稿）」とする。`ingest_inbox`は取り込んだ各ファイルに対しその場でNSFW判定・内容説明取得も試みるため、この順序が自然な流れになる

## 結果

### 良い影響

- inboxフォルダに置いた画像を、完全に手離れした状態で自動的に取り込み・分析まで進められるようになった（オンにした場合）
- 既定でオフのため、既存の「都度手動でingestする」運用は変更なく継続できる
- チェックボックスの切り替えに`watch`プロセスの再起動が不要

### 悪い影響・トレードオフ

- 取り込みは引き続き「移動」であるため、オンにするとinboxに置いたファイルは自動的に（人間の目視確認を経ずに）アプリ管理下のフォルダへ移動される。誤って意図しないファイルをinboxに置いた場合、次のwatchループで自動的に取り込まれてしまう点は運用上の注意点として設定画面にも明記した
- `settings`テーブルのブール値は文字列("0"/"1")として保存しており、他の生成設定（テキスト系）を扱う`update_settings`の「空文字列は無視する」という仕様とは別に、チェックボックス専用の`set_auto_ingest`を用意する必要があった（HTMLのチェックボックスは未チェック時にフォーム値自体が送信されないため）
