# 0005. デプロイ環境（AWS EC2 vs ローカルPC）

- ステータス: 提案中（未決定）
- 決定日: 未定
- 決定者: 未定

## コンテキストと課題

X投稿（[ADR-0002](0002-x-posting-via-playwright.md)）はPlaywrightの永続ブラウザプロファイルに依存し、ヘッドレス環境でのセッション維持が弱いという制約がある（CLAUDE_HANDOFF.md 14章）。この制約のもとで、ワーカーをどこで常駐させるかを決める必要がある。

[ADR-0013](0013-sns-posting-as-logical-plugin.md)で本体（画像管理アプリ）とSNS投稿モジュールを論理的に分離したため、両者を同じ環境にデプロイする必要はなくなった。本体のホスティング先（ローカルWebアプリかAWS常時稼働か）と、Playwright実行環境（本体と同じ場所か、オンデマンドで別途起動するか）は、それぞれ独立して検討できる。

## 検討中の選択肢

**本体（画像管理アプリ）のホスティング先**
- ローカルPC（Windows）でWebアプリとして常時起動（現時点での基本方針）
- AWS常時稼働（EC2等）

**SNS投稿モジュール（Playwright実行環境）**
- 本体と同じ環境で常時起動
- AWS EC2等をオンデマンドで起動し、投稿時のみPlaywrightを実行して終了する（検討中。永続ブラウザプロファイルの保存先をどう永続化するか＝EBSやS3等への同期が別途必要になる）

## 判断軸（README.md / docs/architecture.md 7章にも記載）

| 観点 | ローカルPC常時稼働 | AWS常時稼働（GUI付き） | AWSオンデマンド起動 |
|---|---|---|---|
| Playwright永続プロファイルの維持 | 容易 | ヘッドレスでは弱い | インスタンス起動のたびに永続化されたプロファイルの復元が必要（EBS/S3同期等の追加実装） |
| 24時間稼働の安定性 | PCの状態に依存 | 安定だがGUI付きはコスト増 | 起動の都度失敗しうる（可用性はオーケストレーション実装次第） |
| 初回Xログイン | そのまま可能 | VNC等の追加構成が必要 | VNC等の追加構成が必要（オンデマンド時のみ） |
| 運用コスト | 電気代のみ | インスタンス費用が継続発生 | 投稿頻度が低い（1日数本）ため、常時稼働よりコストを抑えられる可能性 |
| 秘密情報管理 | `.env`のみで完結 | Secrets Manager等の追加設計が必要 | 同左 |
| 実装複雑度 | 低い | 中程度 | 高い（起動オーケストレーション、プロファイル同期、失敗時のフォールバックが必要） |

## 決定

未定。本体のホスティング先は「基本はローカルWebアプリ」の方向で検討が進んでいるが未確定。SNS投稿モジュールのオンデマンドAWS起動案も検討中で、いずれもPhase 3（X Playwright実装）着手前に確定する。
