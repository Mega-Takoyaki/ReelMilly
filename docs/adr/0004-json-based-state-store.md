# 0004. 状態管理はJSONファイルを採用し、DBは使用しない

- ステータス: **非推奨（[ADR-0011](0011-sqlite-state-store.md)により置き換え）**
- 決定日: 2026-09-15
- 決定者: プロジェクトオーナー

> 数万件規模の画像・動画を扱う前提が判明したため、メタデータ管理は[ADR-0011](0011-sqlite-state-store.md)でSQLiteに移行した。本ADRは経緯の記録として残す。監査ログ（`events.jsonl`）についてはJSONLのまま継続する。

## コンテキストと課題

カタログ・last_run・監査ログなどの状態をどう永続化するか。

## 検討した選択肢

- RDBMS（PostgreSQL、SQLite等）
- JSONファイル（`state.json` + `events.jsonl`）

## 決定

JSONファイルを採用する。単一ユーザー・低頻度ジョブという規模において、DBを導入する必要性が薄いため。

## 結果

### 良い影響

- 追加インフラ不要、実装がシンプル
- ファイルをそのまま目視確認できる

### 悪い影響・トレードオフ

- 同時書き込みの排他制御は自前で担保する必要がある（本プロジェクトは単一プロセス運用のため実害は小さい想定）
- データ量が増えた場合の検索性能はDBに劣る
