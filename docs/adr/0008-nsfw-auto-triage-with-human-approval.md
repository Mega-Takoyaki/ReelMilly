# 0008. NSFW自動仕分け＋人間承認ゲートの導入

- ステータス: 決定
- 決定日: 2026-09-25
- 決定者: プロジェクトオーナー

## コンテキストと課題

[ADR-0006](0006-platform-content-rules-from-cream.md)で`content_rating`フィールドを導入したが、その値をどう決定するかは未定義だった。また[TODO.md](../../TODO.md)には、コンプライアンス確認（AI生成であることの明示・年齢表現確認）をシステム化せず運用対応とする方針を記録していた。

今回、NSFWコンテンツ区分について「自動仕分け（一次判定）＋人間の明示的承認（最終判定）」という具体的な仕組みを導入する方針が示された。これにより、自動投稿（drop / x_teaser）の対象を、人間が明示的に承認したアセットのみに限定する。

## 検討した選択肢

- 自動仕分け結果をそのまま`content_rating`として採用し、人間承認は求めない
- 自動仕分け機能を持たず、人間が毎回ゼロから`content_rating`を設定する
- 自動仕分けで一次候補を出し、人間の明示的承認を経て確定させる

## 決定

3番目の案を採用する。

- ingest時にNSFW自動仕分け（分類）を実行し、結果を`nsfw_auto_rating`として`meta.yaml`に記録する。これは**参考値**であり、そのまま投稿判断には使わない
- 確定値`content_rating`は、人間が明示的に承認した場合にのみ設定される（`content_rating_confirmed: true`）
- 自動投稿ジョブ（drop / x_teaser）は`content_rating_confirmed == true`のアセットのみを対象とする。未承認のアセットは自動投稿の対象から除外し、投稿は行わない
- 承認操作は既存のTelegram承認フロー（drop前承認）に統合する。分類結果を通知し、ユーザーが同意または補正した上で承認する形にする
- NSFW自動仕分けの具体的な実装方式（ローカルモデル／外部API等）は本ADRでは決めず、`TODO.md`で別途検討する

### meta.yaml拡張案

```yaml
content_rating: sfw | suggestive | explicit | null  # 確定値。null は未承認
content_rating_confirmed: false                       # 人間による明示的承認フラグ
nsfw_auto_rating: sfw | suggestive | explicit          # 自動仕分けの結果（参考値）
nsfw_auto_confidence: 0.92                              # 自動仕分けの確信度（0.0-1.0、参考値）
```

### ステータス遷移ルール（追加）

`status`を`approved`に進める操作は、`content_rating_confirmed == true`でない限り拒否する。[ADR-0006](0006-platform-content-rules-from-cream.md)のプラットフォーム別ルール検証は、この確定済み`content_rating`に対して行う。

## 結果

### 良い影響

- 自動投稿の対象が必ず人間承認を経るため、コンプライアンス・プラットフォーム規約違反のリスクを抑えられる
- 自動仕分けが一次候補を出すことで、人間はゼロから判断するより承認作業の負荷が下がる

### 悪い影響・トレードオフ

- NSFW分類モデルの選定・運用コスト（精度、誤判定、計算コスト、モデルのローカル実行可否）が新たに発生する
- 分類結果に人間が安易に同調してしまうリスクがある。Telegramの通知文言・UIでは「これはAIによる一次判定であり、最終判断は人間が行う」ことを明示する必要がある
- 本ADRは`content_rating`（コンテンツの露出度合い区分）の決定プロセスのみを扱う。年齢表現確認・AI生成の明示確認は別軸の課題であり、`TODO.md`記載の「運用者が毎回目視確認する」という方針を変更するものではない
