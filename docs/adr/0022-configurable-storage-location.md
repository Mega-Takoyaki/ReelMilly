# ADR-0022: ストレージ(画像・動画の置き場所)を、任意の場所・リムーバブルメディアにできるようにする

- ステータス: 採用
- 日付: 2026-10-07

## 背景

画像・動画のライブラリは`config.yaml`の`paths.library_root`(既定`data/library`)に固定で、容量や運用の都合で
別のドライブ(外付けディスク・USBメモリなどのリムーバブルメディア)に置きたい。リムーバブルメディアは、
起動時に挿さっていないことがある。

## 決定

- 場所は設定画面(「ストレージ」タブ)で変更でき、`settings`テーブルの`storage_root`に保存する。`config.yaml`の値は既定として残す。
  - 方法は2つ: 「コピーして移す」(コピー→検証→DBのパスを付け替え→切り替え。元のファイルの削除は任意)と、
    「すでにファイルがある場所を使う」(ドライブ文字の変更・バックアップの復元用。コピーしない)。
  - 移行は別スレッドで進め、進捗はDB(`storage_job`)に保存して画面が読む。移行中は、取り込み・AI処理を止める。
- **データベース(state)は常にローカル**に置く。ストレージが見つからなくても、アプリは起動でき、設定で直せる。
- 見つからない(`available=False`)間の動作: 画面上部に警告を出し、画像は「見つかりません」の絵、動画は404。
  取り込み・完全削除は理由つきで断り(503)、ワーカーは処理を一時停止し(待機中のタスクは失敗にせず残す)、
  投稿はファイルが見えなければ失敗の記録を残さず見送る。つなぎ直せば、そのまま再開する。
- 別のドライブが同じドライブ文字で挿さっても取り違えないよう、ライブラリに目印(`.reelmilly-library`、中身はライブラリID)を置いて確認する。
  目印が別のライブラリのもの、または目印が無く作品のファイルも見つからない場所は、使わない。
- DBの`file_path`/`wm_path`は絶対パスのまま持ち、場所を変えるときに`<新しい場所>/ready/<作品ID>/<ファイル名>`へ付け替える
  (ライブラリ内の配置が決まっているため)。
- 起動のたびにライブラリのフォルダを作るのは、既定の場所のときだけにする(外れたメディアの代わりに、別ドライブへ空のフォルダを作らない)。

## 影響

- 良い点: 容量・運用に合わせて置き場所を選べる。メディアの抜き差しで壊れない。
- 注意点: DBの絶対パスを付け替える方式のため、ライブラリの外にあるファイルは付け替え対象外。ネットワークドライブの遅さは考慮していない。
- 将来(AWS等へ移す場合)は、この「場所」の抽象を、S3などのオブジェクトストレージへ広げる。
