# 0007. ReelMillyの中核をアセット（画像・動画）管理に据える

- ステータス: 決定
- 決定日: 2026-09-25
- 決定者: プロジェクトオーナー

## コンテキストと課題

当初の引き継ぎ文書（[CLAUDE_HANDOFF.md](../../CLAUDE_HANDOFF.md)）は、Fanvue投稿・X投稿の半自動化を主目的として設計されていた。別プロジェクトCREAM（コンテンツ管理アプリの検討、[ADR-0006](0006-platform-content-rules-from-cream.md)参照）との比較検討を経て、ReelMillyは投稿ワークフローを主役に据えるのではなく、画像・動画のアセット管理（登録・分類・確認・スケジューリング）を土台とし、その上にSNS投稿機能を付加していく形が望ましいと判断した。

## 検討した選択肢

- 投稿ワークフロー（drop / x_teaser / x_engagement）を中心に据え、ライブラリ管理は前段の一機能として位置づける（引き継ぎ文書の元々の構成）
- アセット（画像・動画）管理を中核のドメインとし、SNS投稿はアセットの活用方法の一つとして付加する

## 決定

アセット管理を中核に据える。ディレクトリ契約と`meta.yaml`は「アセットのライフサイクル管理」の一部として捉え、投稿ジョブ（drop / x_teaser / x_engagement）はアセットのステータス遷移における一操作として実装する。

既存のPhase構成（[docs/roadmap.md](../roadmap.md)、Phase 1がライブラリ管理、Phase 2以降が投稿機能）は既にこの位置づけと整合しているため、Phase順序自体の変更は行わない。今後アセットのライフサイクルに関わる機能（NSFW自動仕分け等、[ADR-0008](0008-nsfw-auto-triage-with-human-approval.md)）は、投稿機能と同格ではなく、アセット管理の一部として追加する。

## 結果

### 良い影響

- 将来的にSNS投稿以外のアセット活用方法（別プラットフォーム対応、分類・仕分け機能の拡張等）を追加する際の拡張性が高まる
- アセットのライフサイクル（ingest → 分類・確認 → 承認 → 投稿 → 完了）という一貫した見方で設計を整理できる

### 悪い影響・トレードオフ

- なし。既存設計の位置づけを明確化するものであり、実装済み部分の変更は発生しない
