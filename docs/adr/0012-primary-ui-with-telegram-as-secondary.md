# 0012. 操作・通知インターフェースは画像管理アプリ本体を主とし、Telegramを補助チャネルとする

- ステータス: 決定（[ADR-0001](0001-notification-channel-telegram.md)を置き換える）
- 決定日: 2026-09-26
- 決定者: プロジェクトオーナー

## コンテキストと課題

[ADR-0001](0001-notification-channel-telegram.md)では、通知・操作をTelegramに一本化すると決定した。その後[ADR-0007](0007-asset-management-as-core.md)/[ADR-0010](0010-custom-asset-management-over-eagle.md)で、ReelMillyを画像・動画管理アプリケーションとして自作し、SNS投稿機能はその上に付加する方針に転換した。画像管理アプリ本体が視覚的なUI（一覧・フォルダ・タグ管理、Phase 1.5）を持つことになったため、操作・通知の主役をこの本体UIに移し、Telegramの役割を再定義する。

## 検討した選択肢

- Telegramへの一本化を維持する（[ADR-0001](0001-notification-channel-telegram.md)のまま）
- 本体UIのみで完結させ、Telegramは廃止する
- 本体UIを主な操作画面とし、Telegramは通知＋簡易操作の補助チャネルとして残す

## 決定

3番目の案を採用する。

- 本体（画像管理アプリ）のUIを主要な操作画面とする。一覧・フォルダ・タグ管理、SNS投稿の承認、`content_rating`確定などは、原則として本体UIで完結できるようにする
- Telegramは、以下2つの役割に限定した補助チャネルとして維持する
  - **通知**: 成功・失敗・要ログイン等のプッシュ通知（ADR-0001の「同じ障害を1分に何通も送らない」等の既存ルールは維持する）
  - **簡易操作**: 承認（approve）・スキップ（skip）など、外出先からでも完結できる最小限の操作
- 本体UIとTelegramは同じデータストア（SQLite、[ADR-0011](0011-sqlite-state-store.md)）を参照する。どちらから操作しても状態は一致する
- Telegramでしか行えない操作（初回Xログインの案内等、CLAUDE_HANDOFF.md 9章）は引き続き残す

## 結果

### 良い影響

- 画像・動画を視覚的に確認しながら操作できる、より実用的な運用が可能になる
- Telegramは「外出先からの最小限の操作」に特化することで、実装範囲が明確になる

### 悪い影響・トレードオフ

- 本体UI・Telegramの両方に操作系の実装を持つため、保守対象が増える（承認・スキップ相当の操作を二重実装する）
- 同じSQLiteを両方から更新するため、状態の整合性・同時更新の扱いに注意が必要
