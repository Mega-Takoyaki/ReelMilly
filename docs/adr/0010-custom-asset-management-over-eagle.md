# 0010. 画像・動画管理を自作し、ReelMillyに統合する（Eagle連携は不採用）

- ステータス: 決定
- 決定日: 2026-09-25
- 決定者: プロジェクトオーナー

## コンテキストと課題

既存の画像管理ソフトウェアEagle（購入済み）との連携を検討した。EagleはPlugin API（Eagleアプリ内で動くJavaScriptプラグイン）とWeb API v2（ローカルHTTPサーバー、`http://localhost:41595/api/v2/`）を提供しているが、調査の結果、以下の制約が判明した。

- アイテムのカスタムフィールドが存在せず、`tags`/`annotation`/`star`のみで表現する必要がある。ReelMillyが持つ多数のフィールド（`status`/`fanvue_url`/`price_cents`/`content_rating_confirmed`等）を自然に保存できない
- Web APIはEagleアプリの起動中のみ利用可能。ReelMillyの常駐ワーカーに加えてEagle自体も常時起動が前提になる
- 動画ファイルの扱いなど一部仕様が公式ドキュメントで明記されていない

これらの制約は、Eagleとの連携を「ビューア＋タグミラー」程度の疎結合統合に留めても解消されず、むしろEagle側の仕様変更・起動状態に振り回される依存が増える。

## 検討した選択肢

- Eagle連携（Web API経由でビューア/タグミラーとして統合し、正データはReelMilly側で保持）
- 画像・動画管理を自作し、別リポジトリで独立したサービスとして構築する（CREAM型）
- 画像・動画管理を自作し、ReelMillyに統合する（同一リポジトリ）

## 決定

3番目の選択肢を採用する。画像・動画管理（一覧・フォルダ・タグ管理を含む）をReelMilly自身の機能として実装し、Eagleとの連携は行わない。

別リポジトリでの自作（CREAM型）は、[ADR-0006](0006-platform-content-rules-from-cream.md)/[ADR-0007](0007-asset-management-as-core.md)で既に検討・不採用とした経緯があり、それを覆すだけの理由がないため見送る。ReelMillyはもともと[ADR-0007](0007-asset-management-as-core.md)でアセット管理を中核ドメインに据えており、今回の決定はその延長線上にある。

UIの初期スコープは、フォルダ・タグ管理を含む中規模構成とする。全文検索・AI類似検索等のリッチな機能は当面のスコープ外とし、必要になった段階で追加を検討する。

## 結果

### 良い影響

- 外部アプリ（Eagle）の起動状態やAPI仕様変更に左右されない
- カスタムフィールドを自由に設計でき、ReelMilly固有の状態（`content_rating_confirmed`等）をそのまま第一級のデータとして扱える
- 単一リポジトリでの開発・デプロイに閉じるため、運用がシンプルになる

### 悪い影響・トレードオフ

- Eagleの既製UI（サムネイル一覧、AI意味検索・画像類似検索等）を持たない。同等の使い勝手を得るには自前でUI開発コストを負う
- 購入済みEagleのライセンス費用は今回の用途では活用されない（Eagleを個人的な素材ビューアとして使うこと自体は妨げない）
